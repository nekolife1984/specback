## Phase 7e: Incremental Update

### Purpose

After Phase 7 detects drift, **re-investigate only the affected chapters** (Phase 3
subagent mechanism, chapter-scoped) and apply them with hard safety guards. This is the
"partial update" loop that keeps a maintenance-mode spec alive without regenerating the
whole document.

### Prerequisites

- `{output_dir}/.specback/` with `wbs.json`, `source-map.json`, `trace.json`
- `{output_dir}/drift-report.json` (generated by Phase 7 `detect-drift.py --json`)
- Final spec chapters under `{output_dir}/`

### Procedure

1. **Plan** — identify affected chapters and generate re-investigation prompts:

   ```bash
   python "$(cat {output_dir}/.specback/.skill-path)/scripts/specback-incremental-update.py" \
     plan \
     --specback-dir {output_dir}/.specback \
     --output-dir {output_dir} \
     --json
   ```

   Output: `{specback-dir}/incremental/prompts/<chapter>.md` (one per affected
   chapter) + `{specback-dir}/incremental/state.json` (chapter hash baseline).

2. **Re-investigate** — for each affected chapter, launch a Phase 3 style subagent
   with the generated prompt. The subagent reads the changed sources listed in the
   prompt, updates ONLY the assigned chapter, and saves the result to
   `{specback-dir}/incremental/updated/<chapter>.md`.

3. **Verify** — SRC-ID trap guard + zero collateral edits:

   ```bash
   python "$(cat {output_dir}/.specback/.skill-path)/scripts/specback-incremental-update.py" \
     verify \
     --specback-dir {output_dir}/.specback \
     --output-dir {output_dir} \
     --updated {specback-dir}/incremental/updated/<chapter>.md
   ```

   All `<!-- REF: SRC-NNNN -->` must exist in `source-map.json`; no other chapter
   file may differ from the baseline. Exit 0 = safe to apply.

4. **Apply** — backup + atomic replace + refresh trace:

   ```bash
   python "$(cat {output_dir}/.specback/.skill-path)/scripts/specback-incremental-update.py" \
     apply \
     --specback-dir {output_dir}/.specback \
     --output-dir {output_dir} \
     --updated {specback-dir}/incremental/updated/<chapter>.md
   ```

5. **Confirm full verification** — after all affected chapters are applied, run
   `coverage-check.py` and `gates.py` on the output dir. Both must pass (success
   metric: traceability integrity preserved after the update).

### Phase-specific cautions

- **Never regenerate source-map.json during incremental update** — a re-scan
  renumbers SRC-IDs and silently breaks REFs. If new source files must be added to
  the map, use `restore-sourcemap-from-trace.py` (same idempotency-guard design)
  before applying chapter updates.
- If `verify` reports missing SRC-IDs, do NOT edit the REFs to "make them match" —
  investigate whether the source map was renumbered and restore it first.
- The update loop is chapter-scoped: cross-chapter consistency checks (Phase 4) are
  out of scope for this phase; run them after the whole update completes.
- Each affected chapter should be verified + applied independently, so a failure in
  one chapter never blocks the others.

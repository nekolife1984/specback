## Phase 7: Drift Detection

### Purpose

After Phase 6 delivers the final spec, the codebase continues to evolve. Phase 7 detects which spec sections are potentially affected by source code changes, by cross-referencing `git diff` (or hash snapshots) against `source-map.json` and `trace.json`.

### 🆕 Multi-scope execution

When `goal.multi_scope == true`, the following steps apply:

1. **Determine the current scope**: Read `goal.current_scope` (index into `goal.scopes[]`). Let `scope = goal.scopes[current_scope]`.
2. **Set scope-specific paths**:
   - `SPECBACK_DIR = "{output_dir}/{scope.name}/.specback"` (e.g. `docs/auth/.specback`)
   - `TARGET_ROOT = scope.root` (e.g. `services/auth`)
   - `OUTPUT_DIR = "{output_dir}/{scope.name}"` (e.g. `docs/auth`)
3. **Ensure `.skill-path`**: `mkdir -p {SPECBACK_DIR} && ln -sf $(cat {output_dir}/.specback/.skill-path) {SPECBACK_DIR}/.skill-path`
4. **Run the phase procedure below** using `{SPECBACK_DIR}` as the specback directory (for scripts: `--specback-dir {SPECBACK_DIR}`) and `{TARGET_ROOT}` as the target codebase root (for source-map: `--target {TARGET_ROOT}`).
5. **On completion**: Increment `goal.current_scope` in `{output_dir}/.specback/goal.json`. If `current_scope >= scopes.length`, reset to `0` (all scopes done for this phase).
6. **Resume support**: After each scope completes, save `state.json` with `current_scope` so the session can resume from the correct scope.
7. **At the START of this phase**: If `goal.current_scope > 0` and `goal.multi_scope == true`, this is a resume — skip already-completed scopes and start from `goal.current_scope`.

When `goal.multi_scope == false` (default), run the phase procedure once with `{output_dir}/.specback/` and the project root as before.

### Prerequisites

- `{output_dir}/.specback/` directory with `source-map.json` and `trace.json` (generated by Phase 4 / build-trace.py)
- Phase 6 must have completed (final spec exists)
- `git` repository (for git mode) OR `source-hashes.json` (for hash mode)

---


### Procedure

1. **Mode detection** (auto)
   - `--mode` explicit flag → use that mode
   - Git repo + `state.json.generated_at_commit` present → **git mode**
   - `{output_dir}/.specback/source-hashes.json` exists → **hash mode**

2. **Run detect-drift.py** (with `--json` so Phase 7e can consume the machine-readable report)
   ```bash
   python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" \
     --specback-dir {output_dir}/.specback \
     --output-dir {output_dir} \
     --json
   ```

3. **Review output**
   - `{output_dir}/drift-report.md` — human-readable report listing affected spec sections with impact level (high / moderate / low)
   - `{output_dir}/drift-report.json` — machine-readable version

4. **Ask user** (using AskUserQuestion):
   - "Drift report generated. {N} spec section(s) affected. Would you like to auto-correct REF line numbers? (Phase 7b)"
   - Choices: Yes (proceed to Phase 7b) / No (complete)

5. **If Yes**, proceed to Phase 7b below.

   > **Output artifacts:**
   > - `{output_dir}/drift-report.md` — summary table with file, SRC-ID, impacted sections, impact level, and recommended action
   > - `{output_dir}/drift-report.json` — structured data for tooling

   > **Usage examples (manual invocation):**
   > ```bash
   > # Default (auto mode: git if available, hash if source-hashes.json exists)
   > python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" --specback-dir {output_dir}/.specback
   > # Explicit git mode
   > python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" --specback-dir {output_dir}/.specback --mode git --base v1.0
   > # Hash mode (non-Git projects)
   > python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" --specback-dir {output_dir}/.specback --mode hash
   > # Pipe diff from CI
   > git diff --name-status main...HEAD | python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" --diff -
   > # JSON output
   > python "$(cat {output_dir}/.specback/.skill-path)/scripts/detect-drift.py" --specback-dir {output_dir}/.specback --json
   > ```

### Phase-specific cautions
- Always run from the correct baseline commit. The drift report is only as good as the comparison base.
- Multi-scope: each scope generates its own drift report. Verify the correct scope directory is used.
- Hash mode requires `source-hashes.json` to exist. Run `snapshot-hashes.py` after Phase 6 if using hash mode.
- The drift report is advisory — affected spec sections need manual verification before applying changes. For the automated partial-update loop, proceed to **Phase 7e (Incremental Update)** (`phases/phase-7e-incremental-update.md`): it re-investigates only the affected chapters, guards against SRC-ID renumbering, and enforces zero collateral edits.
